# Storybook

Run it with `npm run storybook`. No build step is needed first — the preview
aliases `@valence-ui/core` and `@valence-ui/utils` to their sources.

## How the sidebar is organised

```
Foundations/
  Materials
Core/
  Buttons/Button
  Buttons/ButtonWithIcon
  …
  Inputs/TextInput
  …
Carousel/
  Carousel
```

**One folder per component**, titled `Core/<Category>/<Component>`. The stories
inside a folder are *cases*, not components:

```
Core/Inputs/TextInput/
  Playground      one instance, driven by the controls panel
  Sizes           every size class
  Radii           every radius class
  Variants        the component's own modes (type, position, direction, …)
  Materials       every material, and coloured variants
  Elevations      the elevation ramp, where the component has one
  Colors          every palette colour
  States          disabled, read-only, required, loading, empty and filled
  Content         the slots and content shapes it accepts
  Composition     the component with, or inside, other components
  Responsive      props that change with the viewport
  Accessibility   focus, labelling, keyboard behaviour
  Edge Cases      empty, overlong, non-latin, and too-narrow parents
```

Not every component needs every case — use the ones that say something about
*that* component. The order above is fixed by a comparator in
`.storybook/preview.ts`, so a story named `Sizes` sorts the same way in every
folder; a story whose name is not in that list sorts after the ones that are.

The point of the split is that a matrix shows a regression by comparison. An
`xs` button beside an `xl` one shows a broken size ramp at a glance; the same
button behind a `size` control does not, because you have to already suspect
the bug to go looking for it.

## Writing a story

Stories are CSF3 objects. The provider and the framing come from preview
decorators, so a story renders only its component:

```tsx
import { Meta, StoryObj } from "@storybook/react";
import {
  Case,
  Matrix,
  Section,
  Showcase,
  Storybook,
  allMaterials,
  sizingControls,
  stateControls,
} from "../../../../storybook";
import { Widget } from "./Widget";

const meta: Meta<typeof Widget> = {
  component: Widget,
  title: "Core/Display/Widget",
  argTypes: { ...sizingControls, ...stateControls },
  args: { children: "Widget" },
};
export default meta;
type Story = StoryObj<typeof Widget>;

export const Playground: Story = {};

export const Sizes: Story = {
  parameters: { valence: { layout: "flow" } },
  render: (args) => (
    <Showcase title="Widget sizes" description="What to look for.">
      <Matrix title="size" values={Storybook.componentSizes}>
        {(size) => <Widget {...args} size={size} />}
      </Matrix>
    </Showcase>
  ),
};
```

### The kit — `packages/core/storybook`

| Export                              | What it is                                                                 |
| ----------------------------------- | -------------------------------------------------------------------------- |
| `Showcase`                          | The page: a padded, scrolling column of sections.                            |
| `Section`                           | One axis of variation, with a title and a description.                       |
| `Case`                              | One labelled instance, optionally with a note and a fixed width.             |
| `Matrix`                            | A `Section` whose cases are generated by mapping over a set of prop values.  |
| `Controlled`                        | Owns the state for one controlled input, so a `map` can produce many.        |
| `Storybook`                         | The value sets to enumerate: sizes, colours, and the awkward test strings.   |
| `allMaterials`, `elevatedMaterials` | Every material / the elevation ramp, as `[label, material]` pairs.           |
| `sizingControls`, `stateControls`, … | Reusable `argTypes` fragments.                                              |

Enumerate from `Storybook` and `allMaterials()` rather than hand-listing
values: when a size or a material is added to the library, every matrix story
picks it up instead of quietly continuing to test the old set.

### Layout

`parameters.valence.layout` positions the story:

- `"centered"` (the default) — centred in a full-height viewport, for a single
  instance.
- `"flow"` — top-aligned and free to grow. Use this for every matrix story.
- `"fullscreen"` — untouched, for components that manage their own full-bleed
  layout (`AppContainer`, `PageContainer`, `Header`, `FloatingToolbar`).

### Controlled inputs

Every input in the library is fully controlled, with no uncontrolled fallback.
Wrap each case in `Controlled` so it owns its own state:

```tsx
<Matrix title="size" values={Storybook.componentSizes}>
  {(size) => (
    <Controlled initial="">
      {(value, setValue) => (
        <TextInput size={size} value={value} setValue={setValue} />
      )}
    </Controlled>
  )}
</Matrix>
```

Components whose state comes from a hook — a `Disclosure`, a `ControlledList` —
cannot use `Controlled`, because a hook cannot be called from inside a `map`.
Give those a small local component per case instead; see `Modal.stories.tsx`.

### The toolbar

Two globals drive the `ValenceProvider`, so any story can be checked in either
colour scheme and against any primary colour without editing its source:

- **Scheme** — `light`, `dark`, or `system`.
- **Primary** — any colour in the default palette.

Story chrome that is not the component under test should set `color="black"`
explicitly. `black` is the palette key that flips with the scheme; inherited
text goes unreadable in dark mode.
